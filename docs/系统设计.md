# 系统设计

## 1. 设计目标与原则

系统以 Python 3.12 为运行基线，围绕“截至 t 日预测 t+1 真实交易日收盘价”建立可复现闭环。设计原则为：时间正确性优先、分层解耦、配置驱动、离线可用、产物可追溯、页面不承载算法、正式结论不依赖伪造数据。

## 2. 总体分层架构

```text
表现层（Streamlit pages / Plotly charts）
        │ 仅调用 service DTO，不直接清洗、训练或计算指标
业务服务层（data / training / prediction / evaluation / experiment services）
        │ 编排用例、校验状态、组织事务和产物
数据与模型访问层（Tushare/CSV/cache repositories, artifact/model stores）
        │ 读写外部数据、缓存、模型、配置和实验文件
领域与算法模块（cleaning/windows/baselines/LSTM/metrics）
        └ 纯计算组件，由服务层调用，不依赖 Streamlit
```

对用户要求的三层映射如下：

| 层 | 责任 | 禁止事项 |
| --- | --- | --- |
| 表现层 | 参数输入、状态展示、图表与文件下载 | 不直接访问 Tushare；不实现清洗、窗口、训练、回测；刷新不自动训练 |
| 业务服务层 | 编排数据准备、训练、预测、评价、实验查询 | 不硬编码路径/Token；不把 UI 状态混入算法 |
| 数据与模型访问层 | 行情源、缓存、CSV、配置、模型和实验产物持久化 | 不决定模型排名；不隐式修改数据语义 |

领域与算法模块作为可测试内核，物理目录位于 `src/data`、`src/baselines`、`src/models`、`src/evaluation`，由业务服务层统一对外暴露。

## 3. 模块设计

### 3.1 数据获取模块 `src/data/providers.py`

- `TushareProvider`：读取环境变量中的 Token，按股票和日期请求日线数据，将外部字段映射为标准字段。
- `CsvProvider`：读取用户指定 CSV，校验编码、字段、股票代码和日期范围。
- 输出统一为标准行情 DataFrame；不在 Provider 内执行模型相关处理。
- Tushare 网络访问由服务显式触发；测试必须注入 mock，不访问真实网络。

建议接口契约：

```text
fetch_daily(ts_code, start_date, end_date) -> MarketDataFrame
load_csv(path, expected_ts_code=None) -> MarketDataFrame
```

### 3.2 缓存模块 `src/data/cache.py`

- 缓存粒度：单股票日线文件；缓存内容为标准字段。
- 逻辑键：`source + frequency + ts_code`；文件名使用安全化股票代码。
- 缓存写入采用临时文件后原子替换，避免中途中断产生半文件。
- 记录 `fetched_at`、请求区间、数据最小/最大日期、行数和数据指纹。
- 增量更新从缓存最大 trade_date 后请求；合并后再次去重、升序和校验。

建议接口契约：

```text
load(ts_code, source='tushare') -> MarketDataFrame | None
save(data, metadata) -> CacheRef
merge(existing, incoming) -> MarketDataFrame
```

### 3.3 数据清洗模块 `src/data/cleaning.py`

处理顺序固定：字段映射与选择 → 类型转换 → 股票代码校验 → 日期解析 → 删除重复日期 → trade_date 升序 → 数值合法性检查 → 缺失处理 → 异常/缺口标记 → 输出质量报告。

- 缺失值只能前向填充，且必须在单股票、按日期升序后进行；首行等无法前向填充的记录丢弃。
- 不使用后向填充、全数据均值或未来时点数据修复历史值。
- OHLC 逻辑异常、负成交量/成交额等按配置选择“拒绝”或“丢弃并记录”，不得静默修改。
- 日期缺口仅识别和报告，不生成虚构交易日。

建议接口契约：

```text
clean_market_data(raw, policy) -> (CleanMarketDataFrame, DataQualityReport)
detect_gaps(cleaned, trading_calendar=None) -> GapReport
```

### 3.4 时间划分与样本构造模块 `src/data/dataset.py`

- 行情按 target_date 的时间顺序切分为 70%/15%/15%，不 shuffle。
- 滑动窗口默认 60 个交易记录；窗口 `[t-window+1, ..., t]` 预测下一真实交易记录 `t+1` 的 close。
- 单变量输入列为 `close`；多变量输入列为 `open, high, low, close, vol, amount`。
- MinMaxScaler 只在训练段可用数据上 fit；目标 close 可使用独立 target scaler，元数据必须说明。
- 验证/测试目标可使用前段尾部作为历史上下文，但窗口目标日期严格落在对应区间。
- 输出样本必须携带 target_date、previous_close、窗口起止日期和 split。

建议接口契约：

```text
split_by_time(data, ratios=(0.70, 0.15, 0.15)) -> SplitBoundaries
fit_scalers(train_data, feature_columns, target_column='close') -> ScalerBundle
build_windows(data, boundaries, feature_columns, window_size) -> WindowedDataset
```

### 3.5 基线模型模块 `src/baselines/`

统一实现 `fit`（如需要）、`predict` 和元数据输出：

- Naive：预测值为 previous_close。
- MA5/MA10/MA20：预测值为目标日前最近 5/10/20 个有效交易记录 close 的算术平均。
- SES：单变量指数平滑，训练/滚动更新策略必须由配置固定并记录。
- ARIMA：单变量模型，`order=(p,d,q)` 和滚动/固定拟合策略必须记录。

所有基线只能读取目标日之前的信息，输出《数据字典》规定的统一预测记录。

### 3.6 LSTM 模型与训练模块 `src/models/`

- `lstm.py`：定义可配置的 LSTM 回归网络。
- `trainer.py`：训练/验证循环、早停、最优权重保存、耗时和历史记录。
- 默认配置：hidden_size=64、num_layers=2、dropout=0.2、batch_size=32、learning_rate=0.001、max_epochs=100、patience=10、MSELoss、Adam、seed=42。
- 保存验证损失最低的 checkpoint；测试集不得进入训练器的早停和选择接口。
- 预测时校验 checkpoint 的特征顺序、窗口、缩放器、股票/数据范围和代码版本元数据。

建议接口契约：

```text
train_lstm(train_set, val_set, config, artifact_store) -> ModelRef
predict_lstm(model_ref, dataset) -> PredictionFrame
load_model(model_ref, expected_metadata) -> LoadedModel
```

### 3.7 回测评价模块 `src/evaluation/`

- `alignment.py`：按 `ts_code + target_date + split` 对各模型预测取公共日期集合，记录每模型原始数量与被剔除数量。
- `metrics.py`：计算 RMSE、MAE、R²、DA 和相对 Naive RMSE 提升率。
- `backtest.py`：面向历史测试目标逐日生成预测记录，不模拟资金交易。
- 排名规则：主要展示 DA 与相对提升率；R²不进入综合排名。

建议接口契约：

```text
align_predictions(frames) -> (AlignedPredictionSet, AlignmentReport)
evaluate(predictions, naive_predictions) -> MetricsRecord
run_backtest(model_or_strategy, evaluation_set) -> PredictionFrame
```

### 3.8 实验管理模块 `src/services/experiment_service.py`

实验状态：`created -> running -> completed | failed`。experiment_id 建议格式为 `YYYYMMDDTHHMMSSZ_<short_hash>`；hash 由规范化配置、数据指纹和种子生成，时间部分便于人工识别。

每次实验保存：

- `config.yaml`：完整解析后的配置快照；
- `manifest.json`：experiment_id、状态、时间、Git 信息（可获得时）、Python/依赖、数据指纹、产物清单；
- `metrics.json`：按模型/数据集记录的指标；
- `predictions.csv`：统一逐日预测格式；
- `training_history.csv`：仅训练型模型的 epoch 历史；
- `alignment.json`、`data_quality.json`、`logs/` 和 `figures/`；
- `models/`：checkpoint、模型元数据和 scaler 文件。

失败实验保留配置、日志和错误摘要，但不得写入伪造指标。

### 3.9 可视化模块 `src/visualization/`

纯函数接收 service DTO 或 DataFrame，输出 Plotly Figure：

- K 线/收盘价与成交量图；
- 实际值—预测值对比图；
- 逐日误差与方向正确性图；
- 模型指标对比图；
- 训练/验证损失曲线；
- 单变量与多变量 LSTM 消融图。

图标题或注释须包含股票、测试日期范围、experiment_id；主对比图不得混入多变量 LSTM。

## 4. 业务服务层设计

| 服务 | 主要方法 | 输入 | 输出 |
| --- | --- | --- | --- |
| `DataService` | `prepare_data`、`get_overview` | 数据源、股票、区间、清洗策略 | 数据引用、质量报告、摘要 DTO |
| `TrainingService` | `train_experiment` | 数据引用、模型与训练配置 | experiment_id、模型引用、状态 |
| `PredictionService` | `predict`、`load_predictions` | 模型/实验引用、目标范围 | 统一 PredictionFrame |
| `EvaluationService` | `compare_models` | 多模型预测引用 | 对齐报告、指标表、排名说明 |
| `ExperimentService` | `create/get/list/export` | 配置或 experiment_id | manifest、产物路径、下载包信息 |
| `VisualizationService` | `build_*_view` | service DTO | 页面可直接展示的数据与图表 |

服务方法应返回可序列化 DTO，不返回 Streamlit 组件。训练必须由 CLI 或页面明确按钮触发；页面加载和刷新只查询状态或读取已存在产物。

## 5. 关键业务流程

### 5.1 数据准备

1. 用户/脚本选择 Tushare、缓存或 CSV，并指定股票与区间。
2. `DataService` 调用 Provider/Repository 获取原始行情。
3. 清洗器输出标准行情和质量报告；缓存层保存可复用结果。
4. 数据指纹由标准字段、排序后内容和清洗配置计算。

### 5.2 训练实验

1. CLI 或显式页面操作提交实验配置。
2. 实验服务创建 experiment_id 并冻结配置快照。
3. 数据模块顺序划分、只在训练集拟合 scaler、构造三段样本。
4. 训练服务只接收 train/val；保存最低验证损失 checkpoint。
5. 训练完成后可由独立评价服务对 test 执行最终预测与评价。

### 5.3 统一回测比较

1. 各模型输出统一 PredictionFrame。
2. 对齐器取公共 target_date，并生成 AlignmentReport。
3. 指标模块基于对齐后的记录计算指标。
4. 评价服务分别生成“传统模型+单变量 LSTM 主对比”和“LSTM 特征消融”结果。
5. 实验服务保存指标、逐日预测和图表。

### 5.4 页面查询

1. 页面选择数据/experiment_id。
2. 表现层调用 service 加载摘要、预测、指标和图表 DTO。
3. 用户切换筛选条件或下载产物；刷新不触发训练。
4. 若显式点击“开始训练”，先展示确认与预计参数，再调用训练服务并显示状态。

## 6. Streamlit 页面结构与用户操作流程

| 页面 | 核心内容 | 用户操作 |
| --- | --- | --- |
| 首页/系统说明 | 系统目标、风险声明、在线/离线状态、最近实验 | 进入数据或实验流程 |
| 数据管理 | 数据源、股票、区间、缓存状态、质量报告、行情图 | 获取/导入、校验、保存缓存 |
| 实验配置与训练 | 数据引用、单/多变量、窗口和超参数、估算信息 | 显式提交训练；不得刷新自动执行 |
| 预测与回测 | 选择已有模型/实验、测试范围、实际与预测曲线 | 运行已配置预测或读取结果 |
| 模型对比 | 主对比表、消融表、指标解释、公共日期报告 | 选择 experiment_id 并导出 |
| 实验记录 | 实验列表、状态、配置、日志、产物、失败原因 | 检索、查看、下载，不在此页训练 |
| 关于与答辩 | 方法说明、数据泄漏规则、离线演示入口、免责声明 | 查看演示清单与版本信息 |

推荐操作主线：数据准备 → 查看质量报告 → 配置并显式启动训练 → 选择已完成实验 → 查看回测与对比 → 导出结果。答辩主线：切换离线模式 → 加载固定 CSV → 选择预训练模型/预生成实验 → 展示数据质量、预测曲线、指标和实验追溯信息。

## 8. 配置设计

配置采用 `configs/*.yaml + 环境变量`：

- `project`：seed、timezone、paths；
- `data`：source、ts_code、start_date、end_date、cache、cleaning_policy；
- `split`：train=0.70、val=0.15、test=0.15；
- `dataset`：window_size=60、feature_set、target_column=close；
- `baseline`：MA 窗口、SES 参数、ARIMA order/更新策略；
- `lstm`：hidden_size、num_layers、dropout、batch_size、learning_rate、max_epochs、patience；
- `evaluation`：metrics、alignment_policy=intersection、ranking_fields；
- `runtime`：device、num_workers、offline_mode；
- `output`：artifact_root、是否导出图表。

秘密只允许通过环境变量（如 `TUSHARE_TOKEN`）注入。配置加载后应校验类型、范围、日期和互斥条件，并将“解析后的最终配置”写入实验快照。

## 9. 模型与实验存储

### 9.1 模型文件

推荐 checkpoint 使用 PyTorch `state_dict`，禁止依赖不透明的整对象 pickle。模型目录包含：

- `model.pt`：state_dict；
- `metadata.json`：model_id、architecture、features、target、window_size、训练/验证日期范围、best_epoch、best_val_loss、seed、数据指纹；
- `feature_scaler.joblib`、`target_scaler.joblib`；
- `config.yaml`：训练配置快照。

### 9.2 实验结果

`artifacts/experiments/<experiment_id>/` 为一次实验的唯一追溯根目录。任何图表、表格或页面结果必须能定位到该目录内的 manifest、prediction 和 metrics。文件路径存储为相对 artifact 根目录的路径，避免固定盘符。

## 10. 异常处理与日志

定义领域异常类型：`DataSourceError`、`SchemaError`、`DataQualityError`、`InsufficientHistoryError`、`LeakageGuardError`、`ModelCompatibilityError`、`TrainingError`、`AlignmentError`、`ArtifactError`。服务层将其转换为用户可理解信息；日志保留技术上下文但不记录 Token。

结构化日志至少包含 timestamp、level、experiment_id、module、event、message；涉及日期对齐时包含 target_count_before/after。

## 11. 离线答辩设计

- 准备经过校验的本地真实行情 CSV 和对应数据质量报告。
- 准备至少一组完整预训练实验产物，含单变量主对比和多变量消融。
- 提供 `offline_mode=true`，完全跳过 Tushare 初始化和网络调用。
- 演示前执行产物完整性检查：文件存在、hash 可验证、模型元数据与输入一致。
- 页面显著显示数据截止日期，避免把历史离线结果表述为实时预测。
- 训练现场演示不是答辩成功的必要条件；优先稳定展示已有可追溯结果，可另用小规模真实数据展示流程。

## 12. 数据泄漏架构防护

1. `fit_scalers` 接口只接受训练数据对象，禁止传入全量 DataFrame。
2. `TrainingService` 只获得 train/val，test 引用由 `EvaluationService` 单独持有。
3. WindowedDataset 保存并校验 `input_end_date < target_date`。
4. 实验 manifest 记录训练/验证/测试目标日期边界和交集检查结果。
5. 对比前强制公共 target_date 对齐；未对齐的直接指标不得进入主表。
6. 预测与指标文件保留 previous_close，支持复核 DA 与 Naive。
7. 页面不能绕过服务层直接改变划分、缩放或评价逻辑。
