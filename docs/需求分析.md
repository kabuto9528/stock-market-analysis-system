# 需求分析

## 1. 文档目的与依据

本文将《开题报告》转化为可实施、可验收的软件需求。项目名称为“基于 LSTM 神经网络的股票价格预测系统”，实现环境统一采用 **Python 3.12**。开题报告中的 Python 3.10 表述由项目级规范升级为 Python 3.12，算法目标和研究范围不变。

核心预测任务固定为：**使用截至第 t 个交易日（含 t 日）的历史数据，预测第 t+1 个真实交易日的收盘价 close**。系统提供研究与教学演示用途的趋势参考，不构成投资建议。

## 2. 用户与使用场景

| 用户角色 | 主要目标 | 典型场景 |
| --- | --- | --- |
| 学习研究者 | 复现时序预测流程、比较模型 | 选择股票与区间，查看数据、预测、指标和实验记录 |
| 个人投资者 | 获得直观的历史与预测走势参考 | 加载已有数据和模型，查看下一交易日或回测预测 |
| 开发/答辩人员 | 运行实验、追溯结果、离线演示 | 使用 CLI 训练并保存结果，在 Streamlit 中只加载成果 |

## 3. 系统边界

### 3.1 范围内

1. 从 Tushare 获取沪深 A 股日线行情，或导入符合数据字典的本地 CSV。
2. 行情本地缓存、增量更新、字段校验、去重、排序、缺失与异常处理。
3. 按时间顺序完成 70%/15%/15% 的训练、验证、测试划分。
4. 构造“历史窗口 -> 下一交易日 close”的监督学习样本。
5. 实现 Naive、MA5、MA10、MA20、SES、ARIMA 和 LSTM 的训练/拟合与预测流程。
6. 开展单变量 LSTM 与传统单变量基线的公平对比，以及多变量 LSTM 特征消融实验。
7. 计算 RMSE、MAE、R²、涨跌方向准确率 DA、相对 Naive 的 RMSE 提升率。
8. 保存模型、配置、指标、逐日预测、耗时、随机种子和环境信息，实现 experiment_id 追溯。
9. 使用 Streamlit 展示数据、模型信息、回测结果、预测曲线和实验对比。
10. 支持无网络、无 Tushare Token 时通过本地缓存、固定 CSV、预训练模型和预生成实验结果完成答辩。

### 3.2 范围外

- 自动下单、模拟交易账户、投资组合优化或收益承诺。
- 分钟级/高频行情、实时行情推送。
- 新闻、公告、社交媒体情感、宏观经济或知识图谱等外部特征。
- Transformer、GRU、复杂集成、自动无边界超参数搜索。
- 将测试集用于调参、早停、模型选择或页面中的临时“试优”。

## 4. 功能需求

### 4.1 数据功能

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-D01 | 支持 Tushare 日线数据获取 | Token 仅来自环境变量；请求参数和响应状态可记录 |
| FR-D02 | 支持本地 CSV 导入 | 校验标准字段、类型、股票代码与日期范围 |
| FR-D03 | 支持行情缓存和增量更新 | 缓存键至少包含 ts_code、数据频率；网络失败可回退本地数据 |
| FR-D04 | 清洗并标准化行情 | trade_date 升序、删除重复日期、数值字段合法、处理缺失和异常 |
| FR-D05 | 识别交易日期缺口 | 连续缺口及处理结果可记录；不得把自然日当交易日补造行情 |

### 4.2 模型与预测功能

| 编号 | 需求 | 验收要点 |

| FR-M01 | Naive 预测 | 使用目标日前一个真实交易日 close |

| FR-M06 | 多变量 LSTM | 输入 open、high、low、close、vol、amount，目标为下一交易日 close |
| FR-M07 | LSTM 训练控制 | MSELoss、Adam、固定种子；验证集早停并保存验证损失最低模型 |

## 6. 核心业务规则

1. 一个样本的输入窗口最大日期必须严格早于 target_date。
2. 验证/测试首个窗口可借用前一区间末尾历史数据，但目标日期必须属于本区间。
3. 日期缺口不通过填造自然日修复；Naive/MA 的“前一日”均指数据中已验证的前一真实交易日。
4. 若无法确认窗口连续对应有效交易记录，则丢弃样本并记录原因和日期。
5. 验证集用于调参和早停；测试集只执行一次最终评价逻辑，不参与选择。
6. 主模型对比：Naive、MA5、MA10、MA20、SES、ARIMA、单变量 LSTM。
7. 多变量 LSTM 只与相同结构的单变量 LSTM 进行特征消融讨论，不混入主对比排名。
8. 模型排名依据 DA 与相对 Naive RMSE 提升率；RMSE/MAE用于误差量级说明，R²仅作参考。

## 7. 主要异常场景

- 未配置 Token、Token 无效、API 限流或网络中断：使用本地 CSV/缓存，说明数据新鲜度。
- CSV 缺字段、重复日期、跨股票混入、日期无法解析、价格非正、成交量/额为负：拒绝或按清洗规则处理并输出报告。
- 样本长度不足窗口或基线所需历史长度：阻止训练/评价并给出最小数据要求。
- 划分后验证集或测试集无有效目标日期：终止实验，不调整顺序来“凑样本”。
- ARIMA/SES 不收敛、LSTM 出现 NaN、模型文件损坏或元数据不匹配：实验标记 failed，不生成伪指标。
- 不同模型预测日期不一致：取公共 target_date，保存差异和丢弃数量；公共集合为空则禁止比较。
- naive_rmse 为 0：相对提升率记为不可定义（null/NaN）并说明原因，禁止除零。

## 8. 验收口径与需求追踪

阶段 0 的验收对象是设计文档而非业务实现。需求、数据字段、接口、实验规则、存储结构和页面流程应能相互引用且无矛盾；系统边界不得扩展到自动交易、情感分析或其他首版外功能。后续实现必须以本文件及《系统设计》《数据字典》《实验设计》为契约，需求变化需先更新文档再实现。
