# 实验设计

## 1. 研究问题与实验目标

本项目在 Python 3.12 环境中回答以下问题：

1. 单变量 LSTM 是否相对“不建模”的 Naive 和传统单变量方法具有可量化增益？
2. 在网络结构、日期范围、窗口、训练规则和评价体系受控时，加入 OHLC、成交量和成交额是否改善 LSTM 表现？
3. 模型能否在严格无时间泄漏、统一目标日期的回测协议下产生可复现结果？

任何正式结论必须来自真实股票日线数据和完整 experiment_id 产物，不使用合成数据替代正式结果。

## 2. 预测任务定义

对按交易日期升序的日线记录，令第 t 个交易日特征为 `x_t`，收盘价为 `c_t`。给定截至第 t 个真实交易日的长度为 W 的窗口：

```text
X_t = [x_(t-W+1), ..., x_t]
y_t = c_(t+1)
```

模型输出 `ŷ_(t+1)`，即下一真实交易日收盘价预测。必须满足：

- `input_end_date = trade_date_t < target_date = trade_date_(t+1)`；
- `previous_close = c_t`；
- 目标不是同日 close，也不是未来多步价格；
- 自然日周末/节假日不生成目标，t+1 指数据和交易日历确认的下一交易日。

默认窗口 W=60 个交易日，约覆盖三个月交易历史，在捕捉中期依赖和保留有效样本数之间折中；阶段 8 仅用 20/30/60 做受控比较，并在后续《数据处理说明》固定说明。

## 3. 数据与样本范围

### 3.1 输入字段

- 单变量：`close`。
- 多变量：`open, high, low, close, vol, amount`，顺序固定。
- 目标：下一交易日 `close`。

不引入技术指标、收益率、新闻、情感、基本面或宏观变量，避免超出开题范围。

### 3.2 数据准备顺序

1. 单股票日线字段校验和类型转换。
2. 按 `trade_date` 升序，删除重复日期。
3. 缺失值仅向前填充；首部缺失或不可信记录丢弃并记录。
4. 标记异常记录和连续日期缺口，不按自然日补造行情。
5. 形成可用目标日期后按时间顺序划分。
6. 只用训练数据拟合 MinMaxScaler。
7. 使用同一 scaler 变换验证/测试数据，构造窗口。

### 3.3 时间划分

- 训练集：前 70% 目标日期。
- 验证集：随后 15% 目标日期。
- 测试集：最后 15% 目标日期。
- 目标日期不重叠，`shuffle=false`。
- 整数边界固定为训练数 `floor(N×0.70)`、验证数 `floor(N×0.15)`、其余归测试集。
- 先统一确定目标日期边界，再构造各模型数据，禁止模型各自重新切分。
- 验证/测试首个样本的输入窗口可借用前一区间末尾历史数据；借用的只是当时已发生信息，目标日期仍必须属于当前区间。

若任一区间因数据量、窗口或缺口过滤而没有有效目标，实验失败并报告，不改变比例或顺序来规避失败。

## 4. 数据泄漏防护协议

| 风险 | 强制防护 |
| --- | --- |
| 排序/重复问题 | 清洗后断言日期严格递增且主键唯一 |
| 全量拟合 scaler | scaler API 只接受训练段；元数据记录 fit_split=train 和日期范围 |
| 窗口含目标日 | 对每个样本断言 input_end_date < target_date |
| 随机切分 | 配置与实现禁止 shuffle；记录三段目标日期 hash |
| 验证/测试混用 | 调参、早停只读 val；test 仅由最终评价流程读取 |
| 保存最后 epoch | checkpoint 必须对应最低 val_loss 的 best_epoch |
| 滚动预测看未来 | 每个 forecast_origin 只能使用该日期及以前数据 |
| 模型日期不齐 | 评价前按公共 target_date 取交集并保存 AlignmentReport |
| 多变量不公平 | 传统基线仅与单变量 LSTM 主对比；多变量只进入 LSTM 消融 |
| 重复查看测试挑模型 | 正式配置冻结后再运行测试；测试结果不得反馈到参数选择 |

## 5. 模型组与预测协议

### 5.1 主对比实验 `main_univariate`

参与模型：Naive、MA5、MA10、MA20、SES、ARIMA、`lstm_univariate`。所有模型只使用 close，并在对齐后的同一测试 target_date 集合评价。

| 模型 | 预测规则 | 可调内容 |
| --- | --- | --- |
| Naive | `ŷ_(t+1)=c_t` | 无 |
| MA5 | 最近 5 个可用交易日 close 均值 | 窗口固定 5 |
| MA10 | 最近 10 个可用交易日 close 均值 | 窗口固定 10 |
| MA20 | 最近 20 个可用交易日 close 均值 | 窗口固定 20 |
| SES | 以截至 t 日的单变量序列生成一步预测 | 平滑参数/估计方式仅由 train/val 决定 |
| ARIMA | 以截至 t 日的单变量序列生成一步预测 | `(p,d,q)` 候选仅由 train/val 决定 |
| 单变量 LSTM | 60 日 close 窗口输出下一日 close | 受控候选，仅由 val 和早停决定 |

正式测试采用扩展窗口的一步滚动（walk-forward one-step-ahead）：预测 target_date 时允许使用截至 previous_trade_date 的真实历史数据。Naive/MA 直接计算；SES/ARIMA 可按固定配置更新/重拟合；LSTM 权重冻结，但输入窗口随时间向前滚动。所有模型都可看到相同 forecast_origin 之前的真实 close，不可看到 target_date 的 close。

SES/ARIMA 的“每步更新”不等于使用未来信息；它只使用在该预测起点已发生的观测。其 order、初始化和更新策略在进入测试前冻结。

### 5.2 LSTM 特征消融实验 `lstm_ablation`

参与模型：`lstm_univariate` 与 `lstm_multivariate`。

控制变量：相同股票、数据区间、70/15/15 边界、目标日期、窗口 W、网络 hidden_size、num_layers、dropout、batch_size、learning_rate、max_epochs、patience、损失、优化器、种子和评价实现。唯一设计差异为输入特征数与特征列表。

若两者因异常过滤产生日期差异，仍取公共 target_date；不得把多变量 LSTM 与传统基线放入同一张主对比表或共同排名。

### 5.3 参数受控实验 `parameter_control`（阶段 8）

采用控制变量法，每次只改变一个因素，候选范围固定：

- window_size：20 / 30 / 60；
- hidden_size：32 / 64 / 128；
- num_layers：1 / 2；
- learning_rate：0.01 / 0.001 / 0.0001。

默认基准为 W=60、hidden_size=64、num_layers=2、learning_rate=0.001。批大小 32、dropout 0.2、MSELoss、Adam、max_epochs 100、patience 10、seed 42 保持不变。候选选择只依据验证集；测试集不用于寻找最佳值。

## 6. LSTM 训练规范

- PyTorch 模型输入形状：`[batch, sequence_length, feature_count]`。
- 输出：每个样本一个缩放空间中的 close，随后反归一化为价格。
- 损失：MSELoss；优化器：Adam。
- epoch 内训练集可在“样本集合不变”的前提下由 DataLoader 打乱批次；这不改变时间划分，也不得跨 split 混合。验证与测试不打乱。
- 同时固定 Python、NumPy、PyTorch、CUDA 随机种子，默认 42；启用确定性设置时记录可能的性能影响。
- 每轮记录 train_loss、val_loss、耗时；验证损失改善时保存 checkpoint。
- 连续 10 轮无改善触发早停；最终加载全局最低 val_loss 的权重。
- 测试标签不得传入训练器，训练器接口只接收 train/val。

## 7. 统一预测结果与日期对齐

所有模型输出《数据字典》的 `PredictionFrame`，至少含：

```text
experiment_id, model_id, model_name, model_family, feature_set,
ts_code, split, forecast_origin_date, target_date,
previous_trade_date, previous_close, actual, predicted,
error, abs_error, squared_error,
actual_direction, predicted_direction, direction_correct, generated_at
```

对齐键固定为 `ts_code + target_date + split`，策略为交集。评价前执行：

1. 验证每模型内部 target_date 唯一、严格升序。
2. 计算全部参与模型的公共 target_date。
3. 保存各模型对齐前数量、剔除数量、公共范围和日期 hash。
4. 仅在公共集合上重算全部指标；禁止将各模型不同样本数的指标直接并列。
5. 公共集合为空时实验失败。

## 8. 指标定义

设公共测试集合样本数为 n，真实值为 `y_i`，预测值为 `ŷ_i`，前一交易日收盘价为 `p_i`。

### 8.1 RMSE

```text
RMSE = sqrt((1/n) × Σ(ŷ_i - y_i)²)
```

越低越好，单位与 close 相同。

### 8.2 MAE

```text
MAE = (1/n) × Σ|ŷ_i - y_i|
```

越低越好，单位与 close 相同。

### 8.3 R²

```text
R² = 1 - Σ(y_i - ŷ_i)² / Σ(y_i - mean(y))²
```

R² 只反映价格水平拟合程度，可能为负；真实值方差为 0 时记为不可定义。**不得以“R² 很高”推出预测精度高，也不得用 R² 排名。**

### 8.4 涨跌方向准确率 DA

定义三分类符号函数：

```text
sign(z) = -1 (z<0), 0 (z=0), 1 (z>0)
actual_direction_i    = sign(y_i - p_i)
predicted_direction_i = sign(ŷ_i - p_i)
DA = (1/n) × Σ I(actual_direction_i = predicted_direction_i)
```

平盘严格按 0 类处理：只有预测方向也为 0 才判为正确。计算使用反归一化后的价格，不使用前后日预测值互比。落盘可使用 0~1，页面以百分比显示。

### 8.5 相对 Naive 的 RMSE 提升率

```text
Improvement(%) = (RMSE_naive - RMSE_model) / RMSE_naive × 100%
```

必须使用同一公共 target_date 上的 Naive RMSE。正值表示优于 Naive，0 表示相同，负值表示劣于 Naive。若 Naive RMSE=0，则该指标不可定义，保存为空并说明，禁止除零。

## 9. 结果解释与模型比较规则

1. 主结论联合考察 DA 与相对 Naive RMSE 提升率，不构造未经论证的综合分数。
2. RMSE/MAE用于说明价格误差量级；R²仅作价格水平拟合参考。
3. 单变量主对比与多变量消融分别成表、分别作图、分别讨论。
4. 若 DA 与提升率结论冲突，应并列说明“方向判断”和“价格误差”的差异，不选择性隐藏指标。
5. 负提升率是有效实验结果，不得删除或改参数后只报告更好结果。
6. 报告公共日期数、日期范围、种子、运行耗时和数据截止日期。

## 10. 实验配置与追溯

一次实验必须冻结并保存：

- 数据源、ts_code、区间、清洗策略、数据 hash；
- 划分比例与三段目标日期边界/hash；
- 特征集、窗口、scaler 元数据；
- 模型参数、训练参数、基线参数；
- Python/NumPy/PyTorch/CUDA 种子和关键版本；
- experiment_id、开始/结束时间、耗时、状态；
- best_epoch、best_val_loss、模型和 scaler 引用；
- 逐日预测、对齐报告、指标、训练历史、日志和图表。

`experiment_id` 是所有模型、预测、指标和图表的关联键。正式实验配置保存在 `configs/experiments/`，解析后的快照保存在 `artifacts/experiments/<experiment_id>/config.yaml`。

## 11. 异常与无效实验判定

以下情况不得产生正式指标，实验状态应为 failed 或 invalid：

- 数据字段或单位无法确认；多股票数据未正确分组；
- 日期非升序、重复日期未处理、目标日期重叠；
- scaler 在训练集以外拟合；
- 样本输入结束日期不早于目标日期；
- 数据量不足、任一 split 无有效样本；
- 关键缺口导致 previous_close 或 MA 历史真实性无法保证；
- 模型输出 NaN/Inf、SES/ARIMA 不收敛且无有效预测；
- 模型元数据与特征顺序/窗口/scaler 不匹配；
- 公共 target_date 集合为空；
- 测试集参与调参、早停或模型选择；
- 缺少配置、种子、预测文件等关键追溯产物。

可部分完成的模型失败时，应保留失败日志；若主对比模型不齐全，不得把残缺结果称为完整主实验。

## 12. 离线答辩实验方案

1. 预先使用真实行情完成至少一个 `main_univariate` 和一个 `lstm_ablation` 实验。
2. 将固定 CSV、数据质量报告、模型、scaler、manifest、predictions、metrics 和图表放入离线演示包。
3. 演示环境设置 `offline_mode=true`，禁止网络调用；页面显示真实数据截止日期。
4. 演示顺序：数据字典与质量 → 预测任务/泄漏防护 → 单变量主对比 → 多变量消融 → experiment_id 追溯。
5. 预留 CLI/页面加载失败的静态图表和 CSV 作为降级展示，但静态内容必须来自同一实验产物。
6. 不在答辩现场依赖长时间训练；可选展示短流程时，明确其仅为流程演示，不作为论文正式结果。

## 13. 阶段性验收检查

后续实现应由自动测试覆盖：排序去重、70/15/15 边界、无目标日期重叠、训练集 scaler、窗口时序、跨区间历史窗口、缺口丢弃、统一预测 schema、公共日期对齐、DA 三分类、提升率和 best checkpoint。Tushare 测试必须 mock，正式实验和测试日志分开保存。
