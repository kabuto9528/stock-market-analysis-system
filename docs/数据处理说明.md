# 数据处理说明

## 1. 处理目标与固定约束

阶段 3 的首要目标是防止未来数据泄漏。标准流程固定为：

1. 类型转换、按 `trade_date` 稳定升序排序、同一交易日保留输入中的最后一条；
2. 数值列只做前向填充（forward fill），禁止后向填充；
3. 删除前向填充后仍缺失的开头记录，并在 `CleaningReport` 记录日期与数量；
4. 按时间顺序划分 train / validation / test；
5. 只使用训练分区拟合特征和目标 MinMaxScaler；
6. 按目标日期所属分区构造窗口，最后再检查目标日期两两不重叠。

标准数值列为 `open、high、low、close、vol、amount`。单变量输入严格为
`close`；多变量输入严格为 `open、high、low、close、vol、amount`，列顺序不得改变。
预测目标固定为下一交易记录的 `close`。

## 2. 清洗规则

- `trade_date` 转为无时区的 `datetime64[ns]`，结果严格升序且日期唯一。
- 行情字段转为 `float64`；无法转换的文本、NaN、正无穷和负无穷均给出清晰错误。
- 缺失值只允许从更早记录向后传播，绝不从未来记录反向填充。
- 如果最早若干行缺少任何标准数值列，它们在前向填充后仍为空，因此整行删除。
- `CleaningReport` 保存输入/输出行数、重复删除数、各列前向填充数、开头删除日期，
  并记录相邻行情记录之间大于 1 个自然日的观察间隔。自然日间隔可能来自周末、法定休市、
  停牌或源数据缺失，不能在没有交易所日历时擅自补造行情。

示例：2024-01-02 的 `close` 缺失，而此前没有记录，则该行不能使用
2024-01-03 的价格回填，必须删除；2024-01-04 的 `close` 缺失时，可以使用
2024-01-03 的 `close` 前向填充。

## 3. 70% / 15% / 15% 时间划分

对清洗后的 `N` 行数据执行连续切片，不调用 shuffle：

- `train_count = floor(N × 0.70)`；
- `validation_count = floor(N × 0.15)`；
- `test_count = N - train_count - validation_count`。

每个分区都保存起止日期、行数以及在完整序列中的起止位置。三个原始日期集合和三个窗口
目标日期集合分别执行两两交集检查。比例不合法或任一分区为空时直接报错。

例如清洗后有 100 行：第 1–70 行为训练集，第 71–85 行为验证集，第 86–100 行为测试集。
边界按实际交易日期保存，而不是按自然日推算。

## 4. Scaler 防泄漏设计

`ScalerManager.fit` 只接受 `split_by_time` 返回的 `TemporalSplit`，内部固定读取
`split.train.frame`。接口不接受任意全量 DataFrame，因此验证集和测试集只能调用 `transform`。
特征与目标 `close` 使用两个独立的 MinMaxScaler。

持久化使用带 SHA-256 完整性校验的 JSON，而不是加载时可执行代码的 pickle。文件保存：

- 特征列及其严格顺序；
- 目标列；
- 特征和目标缩放参数；
- 拟合样本数；
- 训练集起止日期；
- 格式版本。

加载时校验文件摘要、字段集合、参数维度、有限值、特征顺序和目标列。预测结果可通过
`inverse_transform_target` 恢复到真实价格尺度。

防泄漏测试会把验证/测试价格人为设置得远高于训练价格，并断言 Scaler 的 `data_max_`
仍等于训练集最大值；若错误地在全量数据上拟合，该测试必然失败。

## 5. 滑动窗口与日期对齐

默认窗口长度为 60 个交易记录。对目标位置 `t`：

- `X = [t-60, ..., t-1]`，形状为 `(60, 特征数)`；
- `y = close[t]`；
- `previous_close = close[t-1]`；
- 必须满足 `input_end_date < target_date`。

批量数据形状为 `(样本数, 窗口长度, 特征数)`，目标形状为 `(样本数, 1)`。
同时保存目标日期、输入起止日期、原始目标价格和上一交易记录真实收盘价，供后续 DA、Naive
基线与逐日预测复核。

### 具体日期示例

假设窗口长度为 3，训练集最后一天是 2024-01-05，验证集从 2024-01-08 开始：

- 输入窗口：2024-01-03、2024-01-04、2024-01-05；
- 目标日期：2024-01-08；
- `previous_close`：2024-01-05 的真实收盘价。

该验证样本使用训练区间末尾作为历史上下文是允许的，因为所有输入日期都早于目标日期，
且目标日期属于验证集。它不会让 2024-01-08 的值参与 Scaler 拟合。测试集同理：首个测试
目标可以读取验证区间末尾及更早的历史记录，但目标必须属于测试区间。

## 6. 为什么默认窗口是 60

60 个交易日约等于 3 个交易月，能够覆盖短中期趋势、波动和成交量变化，同时不会像过长窗口
那样显著减少训练样本数量或提高 LSTM 参数学习难度。该值是工程默认值而非预设最优结论；
阶段 8 将在控制变量原则下只比较 20、30、60 三个窗口，并仅使用验证集选择参数，测试集只做
最终评价。

## 7. PyTorch 接口

`StockWindowDataset` 返回 `(X, y)` 两个 `float32` Tensor，完整日期元数据保留在
`samples` 属性中。`create_dataloader(s)` 支持固定随机种子；验证集和测试集显式禁止
`shuffle=True`。页面和后续训练服务应调用这些数据层接口，不得自行重复划分、缩放或造窗。
